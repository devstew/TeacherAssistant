# Журнал спостережень асистента вчителя

Веб-застосунок (React + TypeScript, PWA) замість паперового бланку спостережень:
розклад уроків дитини, швидке заповнення бланку на телефоні, експорт документів
і дашборд динаміки навчання й поведінки.

## Структура

```
packages/core/   спільне ядро: бланк, метрики, розклад, моделі документів, парсери Human
apps/web/        веб-застосунок (Vite + React), база в IndexedDB
```

Ядро підключається як сирці (`@journal/core`), окремої збірки не потребує — далі до нього
додасться мобільний застосунок на React Native.

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # тести ядра й вебу
npm run build      # перевірка типів + збірка в apps/web/dist (зі service worker)
```

## Деплой (Vercel)

Vercel визначає Vite автоматично; налаштування — у `vercel.json`
(build `npm run build`, output `dist`, `sw.js` і маніфест без кешування).
Роутинг у застосунку хешовий (`/#/dashboard`), тож переписування шляхів не потрібне.

```bash
git push                       # Vercel збере гілку автоматично
# або разово вручну:
npx vercel --prod
```

Змінні оточення: за потреби `VITE_ENABLE_DEMO=1`, щоб показати демо-дані на проді
(за замовчуванням вимкнені). Збірка тягне `xlsx` із cdn.sheetjs.com — потрібен доступ
до мережі під час встановлення залежностей.

## Демо-дані

**Вимкнені за замовчуванням.** Щоб увімкнути: `VITE_ENABLE_DEMO=1 npm run dev` — тоді
з'являються кнопки на стартовому екрані та в «Налаштування → Дані й резервна копія».
Створюються два профілі:

- **Демо: Андрій К., 4-А** — поточний навчальний рік: розклад і спостереження від 1 вересня
  до сьогодні, останній навчальний день заповнений лише до 2 уроку, підсумок дня порожній.
  Є дні хвороби, день із частковою відсутністю, додатковий корекційно-розвитковий урок,
  теми, коментарі до уроків і примітки. Для щоденного сценарію.
- **Демо: Софія М., 3-Б** — вересень–листопад минулого року з покращенням у листопаді.
  Для дашборду, порівняння місяців і аналітичного звіту.

Файли для перевірки імпорту з Human лежать у `apps/web/demo/`
(`human-oblik-vidviduvannia.xlsx` — відсутності за поточний місяць для «Андрій К.»,
`human-ktp-matematyka.xlsx` — теми з датами на найближчі дні). Перестворити їх:
`npm run demo:files`.

## Що вміє

- **Сьогодні** — уроки дня з тижневого шаблону: предмет, час, тема, «н», статус заповнення.
- **Урок** — бланк як на папері: навчальна діяльність, увага, емоційний стан, поведінка,
  взаємодія з вчителем і асистентом (рівень допомоги, адаптації), хвилини уваги, коментар.
  Автозбереження, копіювання з попереднього уроку.
- **Підсумок дня** — комунікативні та соціальні навички, примітка.
- **Розклад** — тижневий шаблон, дзвінки, канікули, імпорт файлів з Human.
- **Дашборд** — індекси навчання й поведінки, тренди, категорії, теплова карта всіх пунктів
  (% уроків), розподіл допомоги, розрізи за предметами й номером уроку, текстові висновки
  на кшталт «У листопаді дитина показала кращі показники, ніж у жовтні…».
- **Експорт** — щоденний аркуш і журнал за період (PDF/DOCX, копія бланку),
  аналітичний звіт (PDF/DOCX з графіками), сирі дані (XLSX), резервна копія (JSON).

## Human

Публічного API в Human немає (інтеграції лише закриті: Мрія, АІКОМ, AR Book, Microsoft, Zoom),
через «Мрію» дані третім сторонам недоступні. Тому:

- розклад вноситься один раз у застосунку (Human не експортує розклад);
- відсутності — імпорт Excel «Облік відвідування» / «Експорт відвідуваності в Excel»;
- теми — імпорт КТП з Excel (той самий файл, що імпортують у Human).

Розбір файлів — евристичний (`packages/core/src/integrations/human/fileImport/`), з попереднім переглядом.
**Перевірте його на справжньому (знеособленому) експорті зі школи.** Усе проходить через
`HumanDataProvider` — офіційне API, якщо Human його надасть, підключається як `ApiProvider`
(через серверний проксі, щоб не зберігати ключі в браузері).

## Мобільний застосунок

`apps/mobile` — Expo SDK 57 (React Native 0.86), навігація на expo-router, база — SQLite
на самому телефоні. Ядро спільне з вебом: бланк, метрики, розклад і синхронізація —
той самий код, різні лише адаптер сховища й компоненти інтерфейсу.

```bash
npm run mobile            # Expo: QR для Expo Go, клавіші i / a для симуляторів
npm run typecheck         # усі три пакети
```

Збірки для телефона робить EAS — покрокові команди в [apps/mobile/BUILD.md](apps/mobile/BUILD.md),
матеріали для магазинів — у [apps/mobile/STORE.md](apps/mobile/STORE.md), політика приватності —
[PRIVACY.md](PRIVACY.md). Найшвидший спосіб потримати застосунок у руках:
`eas build --platform android --profile preview` дає APK, який ставиться за посиланням,
і для цього не потрібен обліковий запис Google Play.

Стан: працює весь щоденний сценарій — Сьогодні, бланк уроку, підсумок дня, розклад
(тиждень, дзвінки, канікули, імпорт файлів Human), дашборд і експорт. Адаптер SQLite
проходить той самий набір перевірок, що й Dexie у вебі.

Документи на телефоні формуються з того самого HTML, що й у вебі, і друкуються системним
рушієм (`expo-print`), а потім ідуть у «Поділитися»: щоденний аркуш, журнал за період,
аналітичний звіт (PDF) і сирі дані (XLSX). **Word (DOCX) лишається лише у вебі**: бібліотека
docx тягне за собою `Buffer`, `Blob` і `FileReader`, яких у Hermes немає — перевірено на
збірці 9.7.1. Для школи PDF із телефона рівноцінний, а редагований документ роблять у браузері.

Подивитися інтерфейс без телефона можна в браузері: `npm run mobile -- --web` в одному
терміналі й `npm run mobile:web` у другому (проксі на :8082 додає заголовки ізоляції
походження — без них браузерна версія SQLite не стартує). Це лише для розробки.

## Метрики

Схема бланку — `packages/core/src/domain/formSchema.ts` (id пунктів, полярність +1/−1/0, ваги, групи
взаємовиключення). У базі зберігаються лише позначки; показники рахуються на льоту
(`packages/core/src/domain/`: `scoring.ts`, `aggregate.ts`, `insights.ts`), тож зміна ваг у налаштуваннях
перераховує всю історію.

- Частота пункту = уроки з позначкою ÷ уроки із заповненою категорією (уроки з «н» не рахуються).
- Індекс категорії = 50 + 50 × (частка позначених позитивних − частка позначених негативних), 0–100.
- Самостійність = 100 × (1 − підтримка асистента); індекс навчання й поведінки — середні категорій.

## Дані

За замовчуванням усе зберігається локально в IndexedDB цього браузера (Dexie) і нікуди не надсилається.
Резервна копія — JSON у налаштуваннях: і страховка, і перенесення на інший пристрій.

Якщо збірка має ключі Supabase (див. нижче), у налаштуваннях з'являється вхід поштою. Після входу
журнал додатково зберігається у вашому обліковому записі на сервері — так він доступний і з телефона.
Доступ до записів має лише цей акаунт (RLS за `owner_id`); демо-профілі не синхронізуються ніколи.
Спостереження стосуються дитини з ООП — це чутливі персональні дані, тож ведення журналу
й зберігання в хмарі погоджуйте з батьками та адміністрацією школи.

## Синхронізація (Supabase)

> **Статус: перевірено на живому проєкті Supabase** (веб). Міграція застосована, обмін іде
> в обидва боки, правило «перемагає новіший» і правила доступу працюють на сервері так само,
> як у тестах. Вхід кодом із телефона лишається перевірити окремо — вбудована пошта Supabase
> дає кілька листів на годину й для реальних користувачів потребує власного SMTP.

1. Створіть проєкт Supabase і виконайте міграцію `supabase/migrations/0001_records.sql`
   (SQL Editor або `supabase db push`). Вона створює таблицю `records`, політики RLS,
   тригер `server_seq` і процедуру `push_records`.
2. Увімкніть вхід поштою з одноразовим кодом: Authentication → Sign In / Providers → Email,
   вимкніть «Confirm email» посиланням і залиште OTP.
3. Скопіюйте `apps/web/.env.example` в `apps/web/.env.local` і впишіть `VITE_SUPABASE_URL`
   та `VITE_SUPABASE_ANON_KEY` (лише анонімний ключ; service role key на клієнті неприпустимий).
   Ті самі змінні додайте в налаштуваннях проєкту Vercel.

Як це працює: спершу відправка своїх змін, потім завантаження чужих сторінками по 500; курсор —
лічильник сервера `server_seq`, конфлікт виграє запис із пізнішим `updated_at`, а той, що програв,
лишається в журналі конфліктів на вкладці «Синхронізація». Видалення м'які — «надгробок» із часом.
Без ключів застосунок поводиться точно як раніше: локально й без мережі.

Міграцію перевіряє `supabase/tests/run.sh` (потрібен лише Docker): піднімає Postgres, накатує
`0001_records.sql` і проганяє вісім сценаріїв — старіший запис не затирає новіший, час із майбутнього
обрізається, тверде видалення заборонене, другий користувач не бачить жодного чужого рядка
й не може підставити чужий `owner_id`.
